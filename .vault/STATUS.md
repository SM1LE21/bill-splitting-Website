## Blockers

- **apex→www 308 (owner action, Vercel dashboard).** `expensemate.app` 308-redirects to `www.expensemate.app`, but every canonical the site publishes — `metadataBase`, `openGraph.url`, `StructuredData` `SITE_URL`, `robots.ts`, `sitemap.ts` — declares the apex. So the declared canonical host is the one that redirects away. The same 308 breaks Universal Links outright: the iOS entitlement is `applinks:expensemate.app` (apex) and `https://expensemate.app/.well-known/apple-app-site-association` returns 308, which iOS does not follow (verified 2026-07-31; the www host serves it 200). Fix direction is therefore apex-primary, www-redirects-to-apex — not the reverse. Until this is flipped, sitemap URLs and canonicals point at a redirect and Universal Links stay broken.
  - **Elevated 2026-08-04: this is now the only thing blocking Universal Links from this repo's side.** The `appID` case bug — the other half — is fixed. Exact owner steps, Vercel dashboard → the **marketing site** project → Settings → Domains: set **`expensemate.app` as the primary/production domain** and make `www.expensemate.app` the one that redirects to it. Vercel generates the 308 automatically from whichever domain is *not* primary, so this is a toggle, not a rewrite rule; do not try to fix it with a `redirects()` entry in `next.config.ts`, which cannot remove a platform-level redirect.
  - **Verify after flipping, from outside the Vercel edge:** `curl -sSI https://expensemate.app/.well-known/apple-app-site-association` must return **`200`** with **`content-type: application/json`** and **no `Location` header**. A `301`/`302`/`307`/`308` at that URL means Universal Links are still dead — Apple's CDN does not follow redirects when fetching the association.
  - **Then allow for propagation.** The association is fetched by Apple's CDN and delivered to devices on app install/update and periodically after; expect up to ~24h before a device that already has 1.5.0 starts opening `/join` links in the app. A device test the same afternoon proving nothing is not evidence the fix failed. To test immediately, install a development build whose entitlement uses `applinks:expensemate.app?mode=developer`, which bypasses the CDN.
  - **`applinks:expensemate.app` does not cover `www.expensemate.app`.** Any invite that reaches a user on the www host will not open the app even after the flip. Another reason the apex must be primary.
- No current blocker for PostHog website ingestion. If events disappear, first verify browser consent state, ad blockers/privacy extensions, the Vercel `NEXT_PUBLIC_POSTHOG_KEY`, the US Cloud host override, and that the PostHog Activity view is not filtering out internal/test users.

Adding `applinks:app.expensemate.app` is a `Frontend` change that ships with a future iOS build; the file on the web-app host is staged ahead of it. Note also that a Universal Link **does not fire through the 307** — iOS only evaluates the URL the user actually tapped — so the association on this apex domain is the one that matters for invite links.
